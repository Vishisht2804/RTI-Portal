How the Tracks Integrate

1 · Freeze the shared contract

  1. Agree on the Ready-to-File JSON structure.
  2. Create the matching Pydantic model and TypeScript type.
  3. Agree on POST /api/v1/rtis, error format and RTI status values; final jurisdiction is produced by rules, while AI provides only a hint.
  4. Agree on the database ownership boundary.

2 · Build independently with mocks

  1. Person 1 uses mock AI/authority responses while building the complete creation journey.
  2. Person 2 uses a fixed Ready-to-File fixture while building the complete lifecycle.
  3. Neither track should depend on unfinished code from the other person.

3 · Replace the boundary, not the internals

  1. Person 1's final output is passed to POST /api/v1/rtis; the request contains final deterministic jurisdiction, not the AI jurisdiction hint.
  2. Person 2 persists the RTI and takes ownership of its lifecycle.
  3. Person 2's frontend fetches the persisted RTI rather than depending on React state from Person 1.
  4. Do not redesign either vertical slice during integration.

4 · Joint end-to-end verification

  1. Run the happy path from citizen query to dashboard.
  2. Run wrong-jurisdiction and poor-request scenarios; wrong-jurisdiction cases stop before POST /api/v1/rtis.
  3. Run AI failure, unknown authority, payment failure and submission failure.
  4. Fix contract mismatches first; only then polish UI.
